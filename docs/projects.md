# 项目结构与三文件工程

## 项目而非单文件

易语项目以 `.yyproj` 为根清单。入口、模块、窗体和用户代码各自保存，由项目清单和固定命名规则建立关系。

新建可视化项目会生成：

```text
DemoProject/
├─ DemoProject.yyproj
├─ Sources/
│  ├─ Program.yyc
│  ├─ Forms/
│  │  ├─ MainForm.yyx
│  │  ├─ MainForm.Designer.yyc
│  │  └─ MainForm.yyc
│  └─ 工具/
│     └─ 文本.yyc
└─ Resources/
   ├─ ids.xml
   ├─ images/
   ├─ sounds/
   └─ files/
```

- `Sources/Program.yyc`：项目入口。
- `Sources/Forms/MainForm.yyx`：界面与视觉属性。
- `Sources/Forms/MainForm.Designer.yyc`：自动生成的纯代码关系，不手工编辑。
- `Sources/Forms/MainForm.yyc`：事件入口与用户业务逻辑。
- `Resources/ids.xml`：自动生成的窗体、控件和资源标识索引。
- `Resources/images`、`sounds`、`files`：按类型保存工程资源。

纯代码工程可以没有窗体，但源码仍必须位于 `Sources/`。资源目录和资源标识文件始终存在。

## `.yyproj` 工程清单

```json
{
  "格式版本": 1,
  "名称": "DemoProject",
  "包名": "demo.app",
  "源码目录": "Sources",
  "资源目录": "Resources",
  "入口": "Sources/Program.yyc",
  "输出": "DemoProject.exe",
  "启动窗体": "MainForm",
  "源码": [
    "Sources/Program.yyc",
    "Sources/Forms/MainForm.yyc"
  ],
  "窗体": [
    "Sources/Forms/MainForm.yyx"
  ],
  "资源": [],
  "资源标识": "Resources/ids.xml",
  "引用": []
}
```

| 字段 | 说明 |
|---|---|
| `格式版本` | 当前工程格式，值为 `1` |
| `名称` | 项目名称 |
| `包名` | 项目包路径，例如 `demo.app`；源码子目录导入以此为根 |
| `源码目录` | 固定为 `Sources` |
| `资源目录` | 固定为 `Resources` |
| `入口` | 启动源码，`Ctrl+F5` 运行 |
| `输出` | 默认 EXE 文件名 |
| `启动窗体` | 项目启动后打开的窗体名 |
| `源码` | 用户源码和模块，不能包含 `.Designer.yyc` |
| `窗体` | 界面 XML 列表 |
| `资源` | 位于 `Resources/` 下的资源文件相对路径 |
| `资源标识` | 固定指向 `Resources/ids.xml` |
| `引用` | 项目依赖文件 |

入口、源码和窗体必须位于 `Sources/`；资源文件只能放在 `Resources/`。标识文件缺失或目录边界不符合当前规则时会阻止加载。

## 源码目录包

在 `Sources/` 下新建目录即可形成目录包。例如：

```text
Sources/
└─ 工具/
   ├─ 文本.yyc
   └─ 数字.yyc
```

当项目包名为 `demo.app` 时，可用命名导入加载该目录中的全部非生成 `.yyc`：

```text
引入 "demo.app.工具"

输出(取欢迎语())
```

规则如下：

- 导入路径必须以当前工程 `包名` 开头，点号对应 `Sources/` 下的目录层级。
- 目录包只加载当前目录的 `.yyc`，不递归加载子目录；子目录有独立包名。
- `.Designer.yyc` 永远不会进入目录包。
- 目录不存在、目录为空或包名不属于当前项目时会阻止编译并给出预期路径。
- 仍可用 `引入 "工具/文本.yyc"` 精确导入单个文件。

## 资源标识

`.yyx` 中的窗体和控件带有稳定标识，例如：

```xml
<yy:窗体 标识="@id/主窗口" 名称="主窗口">
  <yy:按钮 标识="@id/主窗口/保存按钮" 名称="保存按钮" />
</yy:窗体>
```

`Resources/ids.xml` 集中登记这些标识，并关联图片、声音和文件资源：

```xml
<yy:资源标识 xmlns:yy="urn:yy-studio:resource-ids:1" 格式版本="1">
<yy:界面 名称="主窗口" 标识="@id/主窗口" 文件="Sources/Forms/MainForm.yyx">
    <yy:控件 名称="保存按钮" 类型="按钮" 标识="@id/主窗口/保存按钮" />
  </yy:界面>
  <yy:资源 名称="客户图标" 类型="图片"
           标识="@资源/图片/客户图标"
           文件="Resources/images/客户图标.png" />
</yy:资源标识>
```

该文件由 Studio 生成并在编辑器中只读。项目加载、窗体保存、创建窗体和保存资源表时自动同步。

## 窗体三件套校验

项目加载时，对每个 `Sources/Forms/MainForm.yyx` 自动检查：

1. `Sources/Forms/MainForm.Designer.yyc` 存在；
2. 关系代码包含 `.版本 1` 和唯一的 `界面(...)` 声明；
3. 界面文件名、用户代码文件名和关系声明一致；
4. `Sources/Forms/MainForm.yyc` 存在；
5. 关系代码声明的控件和事件标识在界面中真实存在且类型一致；
6. 用户代码文件出现在源码列表中。

任一检查失败都会阻止项目加载并指出缺失或冲突的文件。Studio 不会静默生成一个可能导致事件丢失的替代文件。

## 事件创建流程

在窗体设计器中双击按钮时：

1. 根据控件名与事件名计算处理程序名；
2. 在用户 `.yyc` 中创建事件子程序和可编辑注释；
3. 把事件映射写入内存窗体模型；
4. 重新生成 `.Designer.yyc`；
5. 切换到用户代码并定位到事件入口。

保存窗体时再次根据界面和事件状态重建关系文件，因此改名、删除控件或切换事件后不会留下陈旧映射。

## 运行、预览与编译

- `F5`：运行当前纯代码文件，或预览当前窗体。
- `Ctrl+F5`：运行项目入口后打开启动窗体。
- `Ctrl+Enter`：预览被设计窗口。
- `Ctrl+B`：编译项目为 Windows EXE。

预览和编译执行用户 `.yyc` 中的函数。自动关系文件负责把真实控件事件解析到这些函数，不作为第二个业务源码参与编译。

## 程序数据树

项目中的每个窗体展开后显示三层：

```text
主窗口
├─ 界面  主窗体.yyx
├─ 关系  主窗体.Designer.yyc
└─ 代码  主窗体.yyc
```

关系文件以只读文本形式打开并提示“自动生成”。用户代码和普通模块进入结构化代码编辑器。

关系代码使用 `界面()`、`控件()`、`绑定()` 声明界面文件、ID 映射和事件处理程序。用户代码可通过 `取控件("@id/窗体/控件")` 按 ID 获取界面元素。

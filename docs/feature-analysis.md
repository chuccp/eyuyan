# 易语言特性核对与易语 3 设计

## 结论先行

易语言的核心竞争力不是“把英文关键字换成中文”，而是把语言、IDE、窗体设计器、组件生态和本土化库打包成一套低门槛的 Windows 开发环境。原版的主要能力可以归为六组：

1. **中文程序语言**：中文关键字、中文标识符、程序集/子程序组织和较宽松的过程式语法。
2. **原生 Windows 开发**：直接编译为机器指令，支持 API、DLL、OCX、COM，带有可视化窗体与事件开发方式。
3. **完整开发环境**：编辑器、项目/程序集、资源、设计器、编译和调试集成在同一 IDE。
4. **库与模块生态**：易模块、支持库、数据库、网络/串口、多媒体、图像和工业控制组件。
5. **本土化能力**：中文日期、简繁转换、全半角、地区字符集、人民币金额和农历等。
6. **低门槛表达**：中文命令、可视化操作和命令帮助，让不熟悉英文的初学者快速进入 Windows 软件开发。

易语言官方还推出过“易语言.飞扬”（EF），加入完全面向对象、跨平台、Unicode、多线程、垃圾回收、静态编译、反射、默认参数和中英文关键字等能力。它代表过“现代易语言”的方向，但与经典易语言是不同语言体系。本项目借鉴其现代化目标，同时优先保留经典易语言的程序组织与中文可读性。

## 易语 3 的新特性

当前 MVP 已加入以下经典版较弱或缺失的开发体验：

- 源码统一使用 UTF-8，支持中文标识符和中文标点字符串。
- 动态数组和键值对象，并支持嵌套访问与赋值。
- 变量、参数和返回值可使用中文类型标注，赋值时持续校验。
- 多标签编辑与 `.yyproj` 项目入口。
- 相对路径 `.ey` 模块引入、重复定义和循环引用诊断。
- 原生窗体设计器，拖放、缩放、多选、对齐和分布控件后用 `.yyx` XML 保存，可直接预览原生窗口。
- `.yyproj` 真实项目结构、窗体 XML 与 `.ey` 代码后置文件，以及可执行的控件单击事件。
- `.yyproj` → C# 代码生成 → 独立 Windows EXE 的真实编译链路，不把易语源码或解析器嵌入运行时。
- JSON 解析与生成，可直接对接现代服务和配置文件。
- 可捕获异常、错误文本和行号级诊断。
- 函数、递归、默认参数、词法作用域和短路逻辑。
- 可取消的长任务；无限循环可以由 IDE 停止。
- 现代 Windows 原生桌面 IDE，不依赖浏览器或 WebView。
- 深色原生编辑器、语法高亮、自动补全、查找、概要、变量与标准库面板。

后续语言/平台特性如下：

- 静态类型推断、可空引用、编译期错误。
- 类、接口、记录、枚举、泛型和模式匹配。
- 异步任务、受控线程和结构化并发。
- 模块命名空间、包管理器和依赖锁定。
- 增量编译、原生单文件输出和崩溃报告。
- 断点、单步、调用栈、作用域变量和热重载。
- 原生窗体设计器：布局、事件、资源、预览和代码同步。
- “自然语言命令”层：允许参数出现在中文句子中的不同位置。

完整的待实现功能、优先级、状态与验收标准见 [功能待办与路线图](roadmap.md)。该文档是后续开发的主清单；新增需求应先进入清单，再安排实现。

## 兼容策略

经典 `.e` 工程是专有二进制工程格式，缺少可依赖的公开格式规范。直接用正则或猜测解析有丢失工程数据的风险，因此本项目采用两条路线：

1. 新项目使用可审查、可版本控制的 UTF-8 文本源码 `.ey`。
2. 旧项目通过导入适配器迁移。优先从原 IDE 可导出的文本、模块和资源建立可验证映射，再逐步覆盖窗体、事件、支持库和 API 声明。

`.ey` 不会被伪装成 `.e` 兼容格式。目标是把迁移过程透明化，而不是给出“能打开但行为不一致”的假兼容。

# 结构化代码格式与旧源码导入

## 为什么不再只保存源码文本

纯源码文本适合编译，但不适合让 IDE 稳定地知道“这是哪个子程序”“这一步在给哪个控件赋值”“这个函数由哪个界面事件触发”。易语 Studio 因此把代码拆成语法模型，再由原生 WPF 视图显示和编辑。

工程由三类文件协作：

| 文件 | 职责 | 关系 |
|---|---|---|
| `.yyproj` | 项目根清单 | 声明入口、源码、窗体和输出 |
| `.yyx` | 窗体结构与事件声明 | 通过 `代码` 指向代码后置 |
| `.yyc` | 子程序、参数、命令和表达式结构 | 与 `.yyx` 中的事件名按函数名关联 |

`.ey` 只作为旧源码兼容入口，不再作为新项目的默认代码格式。

## 打开流程

### `.yyc`

1. 以 UTF-8 读取 XML。
2. 校验根元素、格式版本、已知步骤和容器嵌套。
3. 反序列化为 `YyCodeDocument`。
4. 由结构化编辑器投影为子程序、步骤树和属性面板。
5. 修改后重新生成 XML，不把界面控件状态写进代码文件。

损坏的 XML 会显示行号和列号，并仅在修复场景下回退文本视图；合法文件始终进入结构视图。

### `.ey`

1. 以 UTF-8 读取旧源码。
2. 通过同一套中文词法器和解析器生成 AST。
3. 把 AST 转换为 `YyCodeDocument`。
4. 与 `.yyc` 共用结构化编辑器和组件事件索引。
5. 保存到 `.ey` 时再序列化为兼容源码；另存为 `.yyc` 时保存结构 XML。

导入是语义级转换，不是正则替换。注释、空行和原始缩进不进入 AST，因此结构化编辑后的文本可能被规范化。重要旧文件应先使用“另存为”保留副本。

## `.yyc` 示例

```xml
<?xml version="1.0" encoding="utf-8"?>
<yy:代码 xmlns:yy="urn:yy-studio:code:1"
         格式版本="1"
         名称="主窗体代码">
  <yy:引入 路径="工具.yyc" />
  <yy:子程序 名称="保存按钮_被单击">
    <yy:如果 条件="修剪(姓名输入框.文本) == &quot;&quot;">
      <yy:调用 值="提示(&quot;请先填写姓名&quot;)" />
      <yy:返回 />
    </yy:如果>
    <yy:赋值 目标="标题标签.文本"
             运算符="="
             值="&quot;欢迎，&quot; + 姓名输入框.文本" />
  </yy:子程序>
  <yy:入口>
    <yy:调用 值="输出(&quot;程序启动&quot;)" />
  </yy:入口>
</yy:代码>
```

表达式字段保留中文易语语法，例如 `姓名输入框.文本`、`长度(数组)` 和 `条件 且 条件`。结构元素负责确定步骤类型，表达式负责具体运算。

## 组件与代码关联

窗体只保存对象和事件声明：

```xml
<yy:输入框 名称="姓名输入框"
           文本改变="姓名输入框_文本改变" />
```

代码后置保存对应处理函数：

```xml
<yy:子程序 名称="姓名输入框_文本改变">
  <yy:赋值 目标="标题标签.文本"
           运算符="="
           值="&quot;你好，&quot; + 姓名输入框.文本" />
</yy:子程序>
```

IDE 打开代码后生成只读关联索引：

- 每个控件显示其类型和事件数。
- 每个事件显示是否已有同名子程序。
- 控件名可作为表达式标识符，赋值面板可枚举真实属性。
- 双击控件跳转设计器；点击事件跳转子程序。

索引不写入文件，窗体仍是事件绑定的唯一事实来源。这样修改窗体控件名或事件名后，下次打开代码会立即显示新的关联和缺失项。

## 旧文件迁移

命令行可把旧源码迁移为结构化格式：

```powershell
dotnet run --project tools/YyCompiler.Cli -- `
  --convert .\旧代码.ey .\旧代码.yyc
```

转换后应运行并测试程序，再更新 `.yyproj` 的 `入口`、`源码` 以及 `.yyx` 的 `代码` 路径。

仓库中的 `examples/旧版兼容示例` 是一个保留 `.ey` 文件的完整项目，可用于验证旧源码打开、结构化显示、组件事件定位和编译流程。

## 兼容边界

- `.yyc` 是易语 Studio 自有格式，不冒充经典易语言 `.e` 二进制工程。
- 新旧代码可以互相引入，编译器在加载时把两者统一为 AST。
- 当前结构模型覆盖变量、常量、赋值、调用、条件、循环、遍历、尝试、返回、跳出和继续。
- 尚未覆盖的语法必须继续使用兼容源码，后续新增节点时提升 `.yyc` 的 `格式版本`。

# 易语 Studio 功能待办与路线图

本文档记录所有已确认和计划中的功能，作为后续开发、验收和排期的主清单。完成功能时应同步更新状态与验收结果，不能只在提交说明中记录。

状态说明：

- **已实现**：当前仓库可用，并有测试或人工验收。
- **部分实现**：已有基础能力，但未达到完整目标。
- **待实现**：尚未开始或仅有设计。
- **待验证**：代码已存在，但兼容性、稳定性或公开格式仍有未确认事项。

## 4. P0：编译与交付

原生编译是唯一应用构建路径。解释执行只用于 IDE 中的即时运行和预览，不参与 EXE 发布，也不存在 C#/.NET 兼容分支。

| 编号 | 功能 | 优先级 | 状态 | 验收标准 |
|---|---|---|---|---|
| COMP-01 | 稳定原生中间表示 | P0 | 部分实现 | 已建立 AST → Win64 机器码；尚缺稳定 IR、优化器、源码映射和调试信息 |
| COMP-02 | 静态语义分析 | P0 | 部分实现 | 已报告未定义变量、重复定义、错误参数、类型不符和非法控制流；尚缺完整控制流与不可达代码分析 |
| COMP-03 | 增量编译 | P0 | 待实现 | 改一个文件只重编译依赖链；缓存可验证、可失效 |

| COMP-05 | 自研后端完整性 | P0 | 部分实现 | 数组、对象、文本运行时、资源和完整控件事件逐步进入同一 Win64 后端 |
| COMP-06 | 链接与资源打包 | P0 | 部分实现 | 窗体、控件和资源 ID 已进入原生编译模型；二进制资源、字符串表、字体和版本信息待扩展 |
| COMP-07 | 多目标架构 | P1 | 待实现 | 当前只生成 Win64 x64；ARM64 应在后端原生支持后增加，不复用托管发布开关 |

## 13. 明确边界

- 只读取当前 `.yyproj`、`.yyx`、`.yyc` 和 `Resources` 结构。
- 不宣称“完整兼容某个第三方支持库”。
- 解释执行与原生编译必须共享语义测试，不能出现两套语言行为。
- 所有会执行外部代码、加载 DLL、访问网络或写入文件的功能，都需要明确权限提示和失败路径。
- 窗体设计器以 Windows 原生实现为目标，不引入浏览器内核。

# 系统 SDK 与包

易语 SDK 借鉴 Java/Android 的分层：语言核心提供类似 `java.lang`、`java.util` 的基础能力，SDK 平台组件负责调用操作系统、窗口和控件。SDK 当前版本为 `1`，公开元数据由 `src/Yy.Sdk/YySdk.cs` 维护。

## 包目录

| 包 | 类别 | 能力 |
|---|---|---|
| `系统.基础` | 语言核心 | 基础类型、变量、流程控制和通用转换 |
| `系统.集合` | 语言核心 | 数组、对象、序列和集合算法 |
| `系统.文本` | 语言核心 | 文本操作和转换 |
| `系统.数据` | 语言核心 | JSON 和结构化数据 |
| `系统.界面` | 平台 SDK | 窗口、控件、资源 ID 和界面上下文 |
| `系统.文件` | 平台 SDK | 文件、目录和路径操作 |

包名是公开协议的一部分。新增包、重命名包或删除包都必须同步更新语言解析、编辑器补全、文档和回归测试。

## 导入语法

源码在程序集声明后导入包：

```text
.程序集 客户登记

导入包 "系统.基础"
导入包 "系统.集合"
导入包 "系统.界面"

取控件("@id/主窗口/保存按钮").文本 = "已保存"
```

规则如下：

- `导入包` 位于顶层声明区，不进入子程序或执行语句块。
- 包名必须使用文本字面量，未知包会得到带可用包列表的诊断。
- 根文件和被引入模块中的包声明会去重后合并。
- 易语言视图、纯代码视图和 `.Designer.yyc` 使用同一条导入语法。
- 在 `导入包 "` 后触发补全会列出当前 SDK 包，不必记忆包名。

当前已按导入包限制内置函数可见性。语言核心包描述编译器自身提供的能力，平台 SDK 包连接宿主操作系统；未导入时诊断会给出应添加的 `导入包`。类型与成员级隔离、外部包仍属于后续阶段。

系统 SDK 包和项目源码目录包使用不同关键字：

```text
导入包 "系统.界面"
引入 "demo.app.工具"
```

`导入包` 解决外部系统能力；`引入` 解决当前工程内部的源码目录依赖。项目包名保存在 `.yyproj`，点号映射到 `Sources/` 下的目录层级。

## 界面封装

界面 API 借鉴 Swing 的分层方式，把“控件界面、上下文、具体 UI 实现”拆开。`Yy.Sdk` 不引用 WPF；Studio 预览使用设计器适配层，编译产物使用 Win32 原生适配层：

| 类型 | 职责 |
|---|---|
| `IYyContext` | 窗体标识、按资源 ID 获取控件、取得宿主服务 |
| `IYyUiElement` | 所有界面元素的标识、名称、类型和通用属性访问 |
| `IYyWindow` | 窗口标题、宽度和高度 |
| `IYyControl` | 控件文本、可见性和启用状态 |

用户代码首选通过稳定资源 ID 访问界面：

```text
变量 保存按钮 = 取控件("@id/主窗口/保存按钮")
保存按钮.文本 = "正在保存…"
保存按钮.启用 = 假

取控件("@id/主窗口").标题 = "客户登记 · 已保存"
```

同一段代码在 Studio 预览和编译后的 Windows 程序中使用相同 ID 映射。控件名称只用于设计器显示和旧表达式兼容，不应作为资源关联协议。

## 当前边界

本轮只建立最小可用基线：

- 四个语言核心包、两个平台 SDK 包及其公开说明。
- `导入包` 解析、源码往返、模块合并、补全和错误诊断。
- 跨 UI 技术的窗口与控件契约。
- `@id/...` 控件访问在预览中映射到设计器对象，在编译产物中映射到 Win32 窗口句柄。

外部包安装、语义版本、可见性控制、类型与成员按包隔离、事件订阅、布局容器和 Swing 式组件构造仍属于后续阶段。包管理器规划见 [路线图](roadmap.md)。

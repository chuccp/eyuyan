# 系统 SDK 与包

易语 SDK 提供类似 JDK 的稳定能力边界：语言、编辑器、预览和编译器通过同一组包名识别系统能力。SDK 当前版本为 `1`，公开元数据由 `src/Yy.Sdk/YySdk.cs` 维护。

## 包目录

| 包 | 能力 |
|---|---|
| `系统.基础` | 基础类型、变量、流程控制和通用转换 |
| `系统.界面` | 窗口、控件、资源 ID 和界面上下文 |
| `系统.文件` | UTF-8 文件、目录和路径操作 |
| `系统.数据` | JSON、数组、对象和数据转换 |

包名是公开协议的一部分。新增包、重命名包或删除包都必须同步更新语言解析、编辑器补全、文档和回归测试。

## 导入语法

源码在程序集声明后导入包：

```text
.版本 1
.程序集 客户登记

导入包 "系统.基础"
导入包 "系统.界面"

取控件("@id/主窗口/保存按钮").文本 = "已保存"
```

规则如下：

- `导入包` 位于顶层声明区，不进入子程序或执行语句块。
- 包名必须使用文本字面量，未知包会得到带可用包列表的诊断。
- 根文件和被引入模块中的包声明会去重后合并。
- 结构化代码、纯代码和 `.Designer.yyc` 使用同一条导入语法。
- 在 `导入包 "` 后触发补全会列出当前 SDK 包，不必记忆包名。

当前阶段，包导入负责声明依赖和完成格式校验；语言内置命令仍按全局命令解析，按包限制可见符号属于下一阶段。

## 界面封装

界面 API 借鉴 Swing 的分层方式，把“控件界面、上下文、具体 UI 实现”拆开。`Yy.Sdk` 不引用 WPF，预览和编译产物使用各自的适配层实现这些契约：

| 类型 | 职责 |
|---|---|
| `IYyContext` | 窗体标识、按资源 ID 获取控件、取得宿主服务 |
| `IYyUiElement` | 所有界面元素的标识、名称、类型和通用属性访问 |
| `IYyWindow` | 窗口标题、宽度和高度 |
| `IYyControl` | 控件文本、可见性和启用状态 |

用户代码首选通过稳定资源 ID 访问界面：

```text
变量 保存按钮 = 取控件("@id/主窗口/保存按钮")
保存按钮.文本 = "正在保存…"
保存按钮.启用 = 假

取控件("@id/主窗口").标题 = "客户登记 · 已保存"
```

同一段代码在 Studio 预览和编译后的 Windows 程序中使用相同 ID 映射。控件名称只用于设计器显示和旧表达式兼容，不应作为资源关联协议。

## 当前边界

本轮只建立最小可用基线：

- 四个系统包及其公开说明。
- `导入包` 解析、源码往返、模块合并、补全和错误诊断。
- 跨 UI 技术的窗口与控件契约。
- `@id/...` 控件访问和预览、编译产物中的统一解析。

外部包安装、语义版本、可见性控制、类型与成员按包隔离、事件订阅、布局容器和 Swing 式组件构造仍属于后续阶段。包管理器规划见 [路线图](roadmap.md)。

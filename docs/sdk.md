# 系统 SDK 与包

易语 SDK 借鉴 Java/Android 的分层：语言核心提供类似 `java.lang`、`java.util` 的基础能力，平台包负责操作系统、网络和设备服务，工具链包负责项目构建与自举。

SDK 版本为 `1`，包目录、成熟度和依赖关系由 `src/Yy.Sdk/YySdk.cs` 统一维护。包名是语言解析器、编译器、Studio 补全和文档共享的公开协议。

## 包状态

| 状态 | 含义 |
|---|---|
| 预览 | 已有解释器实现，原生后端仍在补齐；允许导入 |
| 规划中 | 包目录与依赖已经确定，但实现尚未完成；禁止导入 |

禁止把规划中的包伪装成可执行 API。包只有在解释器、原生后端、补全、诊断和测试全部接通后才能从“规划中”升级为“预览”。

## 导入语法

源码在程序集声明后导入包：

```text
.程序集 客户登记

导入包 "系统.基础"
导入包 "系统.集合"
导入包 "系统.界面"

取控件("@id/主窗口/保存按钮").文本 = "已保存"
```

规则如下：

- `导入包` 位于顶层声明区，不进入子程序或执行语句块。
- 包名必须使用文本字面量。
- 未知包会列出当前可导入包。
- 规划中的包会得到“已登记，但尚未实现”的诊断。
- 补全只列出当前可导入包，避免生成无法编译的源码。
- 根源码和被引入模块的包声明会去重后合并。

项目内部代码使用 `引入`，不使用 `导入包`：

```text
导入包 "系统.界面"
引入 "demo.app.工具"
```

## 原生界面契约

界面 SDK 不使用 `object`、反射或宿主对象。标识、句柄和值都使用固定协议，确保设计器、Win32 编译产物和未来自举运行时可以共享同一套 API：

| 类型 | 职责 |
|---|---|
| `YyNativeHandle` | 窗口或控件原生句柄；零值无效 |
| `YyUiValue` | 无装箱布尔、整数、文本和句柄值 |
| `YyUiElement` | 稳定标识、名称、控件类型和原生句柄 |
| `YyUiProperty` | 文本、标题、位置、尺寸、可见、启用、选中和图片属性 |
| `IYyContext` | 按稳定 ID 查找句柄并读写属性 |
| `IYyUiHost` | 显示、消息循环和关闭窗口 |

控件名称只用于设计器显示，用户代码必须通过稳定 ID 访问：

```text
变量 保存按钮 = 取控件("@id/主窗口/保存按钮")
保存按钮.文本 = "正在保存…"
取控件("@id/主窗口").标题 = "客户登记 · 已保存"
```

SDK 公开契约不得重新引入 WPF 控件类型、CLR 对象属性或泛型服务定位。Studio 设计预览通过内部适配器实现这些契约；用户程序由 Win32 后端直接实现相同语义。

## SDK 升级门槛

规划包升级为预览包前必须同时满足：

1. 解释器行为和诊断完成。
2. Win64 原生后端完成同等行为。
3. Studio 补全、参数提示和 F1 帮助接入。
4. 包依赖、错误码、取消和资源释放规则有文档。
5. 正常、失败和资源泄漏测试通过。

类型与成员级隔离、语义版本和外部包安装仍属于后续能力。
